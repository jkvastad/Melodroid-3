# CLI Reference

Every command writes its artifact under `output/<category>/` and prints the path. Shared
good-fraction options appear on most commands: `--max-size` (default 24), `--max-prime` (default
5), `--max-lcm` (default 24), `--ktet` (default 12).

## Tables

### `good-fractions`

```bash
melodroid table good-fractions [--max-size 24] [--max-prime 5]
```

Prints the good fractions for the given size/prime limits.

### `lcm-families`

```bash
melodroid table lcm-families [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Prints the LCM families, ascending by LCM, empty families omitted.

### `bin-overlaps`

```bash
melodroid table bin-overlaps [--max-size 24] [--max-prime 5]
```

For each adjacent pair of good fractions, the bin radius
$c = (\text{Upper} - \text{Lower}) / (\text{Upper} + \text{Lower})$ at which their JND bins first
touch. The caption reports the minimum $c$ — the binding constraint.

### `octave-sweep`

```bash
melodroid table octave-sweep --ratios 1.0 1.25 1.5 \
  [--sweep-step 0.001] [--bin-radius 1/161] [--only-full-matches] \
  [--only-centered-full-matches] [--max-size 24] [--max-prime 5]
```

Sweeps a reference ratio across $[1, 2)$, binning each input ratio against the good fractions;
flags full matches and centered full matches. `--ratios` is required (space-separated decimals on
$[1, 2)$).

Strict full matches are highlighted green. When a ratio falls in two overlapping bins
(only possible at radius $\geq 1/161$ for defaults), the row is flagged ambiguous: each competing column is
filled with a `~` prefix and the row is highlighted yellow; its LCM cell shows the **minimum**
LCM across candidate readings with a `?` suffix (e.g. `9?`).

Some common reference sets:

- (LCM 4) `1.0 1.25 1.5`
- (LCM 8) `1.0 1.125 1.25 1.5 1.875`

### `ktet-cutoffs`

```bash
melodroid table ktet-cutoffs [--max-k 50] [--only-strictly-improving] \
  [--max-size 24] [--max-prime 5]
```

Lists the worst-case covering radius $c_k$ per $k$, its limiting fraction, and the nearest key.

### `key-sweep`

```bash
melodroid table key-sweep --ktet 12 (--keys 0 4 7 | --ratios 1.0 1.25 1.5) \
  [--bin-radius c_k] [--only-full-matches] [--max-size 24] [--max-prime 5]
```

Like the octave sweep but stepping through the $k$ keys of the tuning. At least one of `--keys` /
`--ratios` is required; both may be combined.

### `placement`

```bash
melodroid table placement --lcm 4 [4 ...] --at 0 \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Prints the keys and fractions for one or more LCM placements at a shared anchor.

### `renormalizations`

```bash
melodroid table renormalizations --lcm 24 \
  [--max-size 24] [--max-prime 5] [--max-lcm 24] [--approximate] [--per-snap-c] \
  [--lcm-tradeoff] [--max-c 0.05] [--placements] [--ktet 12]
```

Renormalizes one LCM family onto each of its member fractions, printing a row per base (the trivial `1/1` base reproduces the family). The `Count` column reveals which renormalizations collapse fractions together, exposing the family's isomorphism structure. The `LCM` column gives the wave pattern length (LCM of denominators) of each renormalized set — for non-unison bases this often exceeds the family's own LCM as images fall off the good-fraction grid. In `--approximate` mode an additional `LCM ✓` column reports the wave pattern length after snapping to nearest-good fractions (shown as `—` on rows that were already all-good).

Renormalization preserves prime smoothness but not size, so some bases produce fractions that
exceed `--max-size` and are therefore *not* good fractions (e.g. `16/9 ÷ 9/8 = 128/81`).
`--approximate` snaps each such image to its nearest good fraction (multiplicative
[bin distance](../theory/cluster-ranges.mdx), `c = |b − a| / (b + a)`) and adds columns: the
non-good images are highlighted, `→ good` shows the resulting all-good set, and `c` / `c %` give
the smallest bin radius that makes the whole renormalization good — the largest snap it required —
as an exact reduced fraction and a percentage to compare against the ~0.5–1 % pitch JND. Rows that
are already all-good show `—`. For lcm 18, base `16/9` renormalizes into the lcm-24 major scale at
`c = 1/161 ≈ 0.621 %` — exactly the syntonic comma the cluster-ranges page highlights.
`--per-snap-c` (companion to `--approximate`) additionally annotates each snapped `→ good` value
with the exact bin radius that individual snap required, as `fraction, %` in parentheses (e.g.
`5/3 (1/161, 0.621 %)`); already-good values are left plain.

`--lcm-tradeoff` (companion to `--approximate`) adds an `LCM↔c options` column exposing the tension
between snap accuracy and wave pattern length. Nearest-good snapping lets each image chase its own
closest good fraction, so denominators diverge and the LCM can balloon far past 24. Instead, for
each candidate LCM cap `L` in `1..--max-lcm`, every image is snapped to the nearest good fraction
whose denominator divides `L` — deliberately accepting a worse per-fraction snap so the chosen
denominators share more factors and hold the overall LCM low. Each row lists the resulting Pareto
frontier, one `LCM → c %` breakpoint per line (lowest LCM bolded): smaller LCM costs a larger
radius. `--max-c` (default `0.05`, i.e. 5 % — intentionally above the ~0.5–1 % JND to leave the
frontier room) caps how large a bin radius a snap may cost; caps no assignment can satisfy within it
are omitted, and a row with no feasible option shows `—`. For lcm 24 renormalized onto `5/3`,
nearest-good snapping balloons to an lcm-120 set at only `0.621 %`, but the frontier shows the same
renormalization can be held to lcm ≤ 24 for about `2 %` — the price of a recognizable pattern.

`--placements` (companion to `--approximate`) adds a `Placement` column re-expressing each rotation
as a `--ktet` (default 12) placement. Renormalising onto member fraction `b` re-roots the same keys
on the key `k` where `b` sits, so the snapped set reads as another family `L'` there: `= L'@k` for an
exact isomorphism, `⊆ L'@k` for a renormalised proper subset. Only rotations reaching a good LCM
(`L' ≤ --max-lcm`) entirely within the syntonic comma (`c ≤ 1/161`) are placed; those that balloon
past `--max-lcm` or overshoot the comma show `—`. See
[renormalisation and isomorphism](../theory/lcm-families.mdx#renormalisation-and-isomorphism)
for the underlying family relations.

### `family-overlap`

```bash
melodroid table family-overlap --lcm-sweep 4 --lcm-ref 24 \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Sweeps one LCM shape against a reference family; green rows sit wholly inside the reference.

### `key-supersets`

```bash
melodroid table key-supersets --keys 0 4 7 [--compare 0 3 7] [--collapse] \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Lists every placement whose keys contain the requested set, tightest fits first. `--keys` accepts any integer and octave-normalizes it into `[0, ktet-1]` (e.g. `14 → 2`, `-1 → ktet-1`). Pass `--compare` with a second key set (normalized the same way) to split the supersets into three tables: **Common** — placements that are a superset of both sets (matched by `(lcm, at)` identity) — then those unique to `--keys` and unique to `--compare`. `--collapse` folds placements that cover the **same keys** (isomorphic families sweep out identical key patterns, so e.g. `3@7` and `4@0` both land on `0 4 7`) down to the lowest-LCM representative — handy for reading a single key's placement hierarchy without the isomorphic redundancy.

### `superpositions`

```bash
melodroid table superpositions --keys 0 2 4 5 7 9 11 \
  [--min-block-lcm 2] [--max-block-lcm 24] [--max-results 200] [--any-reference] \
  [--collapse-aliases] [--reference 0 7] \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Lists minimal/irredundant ways to cover `--keys` as a union (superposition) of LCM-family placements, fewest pieces first. A building block may extend past the target; each row reports its extra keys (union minus target) and whether the pieces partition the target (`Disjoint?`). Every piece uniquely covers at least one target key. `--keys` octave-normalizes like `key-supersets`. Restrict the building blocks with `--min-block-lcm` / `--max-block-lcm` — e.g. `--min-block-lcm 8 --max-block-lcm 12` composes the target from the 8/9/10/12 families alone. `--max-results` caps the listing.

By default only **unique-reference** decompositions are listed: every piece shares one reference key (anchor), shown in the `Ref` column. The reference of a placement `L@a` is its anchor `a` — the key where the family's fundamental (`1/1`) sits — so a unique-reference cover roots the whole sound on a single fundamental. Isomorphic families are handled as aliases: the same keyboard key-set reachable by different families at shifted anchors (e.g. `4@0` and `3@7`, or `8@0` and `12@7`) lets a piece join whichever reference its partners share. With `--min-block-lcm 8 --max-block-lcm 12` this exposes the major scale as `8@0 + 12@0` (rooted on key 0, no extras) — the shared-reference alias of the cross-anchor `8@0 + 8@5`. Because the pieces share a fundamental, the whole superposition's wave pattern length is the `lcm` of their family LCMs, shown in the `LCM` column: for `8@0 + 12@0` that is `lcm(8, 12) = 24` — the very pattern of the single-piece `24@0` cover.

Pass `--any-reference` to drop the shared-reference requirement and list every minimal cover (pieces may sit at different anchors, the `Ref` column is omitted); that is where mixed-reference identities such as the major scale `= 8@0 + 8@5` and the natural minor `= 8@1 + 8@6` appear.

Two flags cut the listing down to the interesting rows. `--collapse-aliases` folds together decompositions that produce the identical union at the same reference **with the same piece count** — the isomorphic/renormalisation aliases such as `5@0 + 8@0` = `8@0 + 10@0` = `8@0 + 20@0`, or `4@7 + 15@7` = `12@7 + 15@7` = `20@7 + 15@7` — keeping one lowest-LCM representative per group (piece count is part of the grouping, so a genuinely different cover with more, smaller pieces is never mistaken for an alias). `--reference 0 7 …` restricts the listing to unique-reference decompositions anchored on the given key(s) (octave-normalized like `--keys`); it is incompatible with `--any-reference`, which has no single anchor to filter on. Together they answer "what are the distinct ways to build this key set rooted on its tonic or dominant?" — e.g. `--keys 0 2 3 5 7 8 11 --collapse-aliases --reference 0 7 2` reduces the harmonic minor scale's 55 raw rows to its handful of tonic/dominant two-piece fits.

### `voicings`

```bash
melodroid table voicings (--lcm 24 | --keys 0 4 7) \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Lowest-penalty voicings from each root. Exactly one of `--lcm` / `--keys`.

### `subsets`

```bash
melodroid table subsets (--lcm 15 [--at 0] | --keys 0 4 7) \
  [--ktet 12] [--bin-radius <c>] [--only-full-matches] [--max-results 200] \
  [--ambiguous-matches 1] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Enumerates every size-≥2 subset of the base key set (an `--lcm@--at` placement or a literal
`--keys` set) and key-sweeps each one. Output is a matrix: one row per subset, one column per
reference key `n`, with each cell holding the LCM the subset full-matches at that reference. This
surfaces the renormalized-subset relations of the `graph lcm-families` output at the keyboard
level — e.g. `--lcm 15` reveals subsets that full-match LCM 20. Ambiguous full matches (marked
with a trailing `?`) are included by default; `--only-full-matches` restricts to strict matches.
An ambiguous cell can full-match more than one LCM family; `--ambiguous-matches` (default 1) sets
how many candidate LCMs each ambiguous cell lists, ascending best-fit (shortest wave pattern
length) first — e.g. `--ambiguous-matches 2` shows `8? 9?`. `--max-results` caps the number of subset rows. Exactly one of
`--lcm` / `--keys`. `--bin-radius` defaults to the `c_k` cutoff (as in `key-sweep`).

### `chord-melody`

```bash
melodroid table chord-melody --chord-keys 0 4 7 \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24] [--drop-renormalized-subsets] [--drop-collapsed] [--stable-15]
```

Matrix of maximal-LCM placements containing the chord vs each key. *Maximal* means a family
that is not a **literal** subset of another allowed family; a renormalized subset that is not
also a literal subset is kept as its own row. Isomorphic families (renormalizations of one
another, whose placements coincide) are collapsed to the lowest-LCM representative.

`--drop-renormalized-subsets` also treats a renormalized subset of a larger allowed family as
dominated, filtering those rows out (the stricter pre-collapse view).

`--drop-collapsed` drops each unstable placement whose collapsing key is one of the chord keys —
under the [preference principle](/docs/music/preference) it has already collapsed onto a
smaller/simpler pattern and is redundant. Two families are unstable: an lcm-15 placement `15@x`
(collapsing key `(x+8) mod 12`, collapsing onto the adjacent `24@(x+1)`/`24@(x+8)`), and an lcm-20
placement `20@x` (collapsing key `(x+3) mod 12`, since `20@x` is the subset of `15@(x+7)` and
collapses to it). 12-tet only; no effect on other families or ktets.

`--stable-15` instead keeps each lcm-15 row but shows it in its **stable form** `15s@x`: the
collapsing key `(x+8) mod 12` is dropped from the row and the label becomes `15s` (e.g. `15@3`'s
full `0 1 3 4 6 8 11` becomes `15s@3` = `0 1 3 4 6 8`). 12-tet only. Combine with `--drop-collapsed`
to first remove the rows that collapsed onto a chord key, then stabilise the survivors.

### `scale-fingerprint`

```bash
melodroid table scale-fingerprint --chord-keys 0 4 7 \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Matrix for **playing melody with chords**. Rows are the six named scales — **major**,
**harmonic minor**, **melodic minor**, **bebop dominant**, **harmonic major**, **major blues** —
each transposed to every anchor (= root) whose key set fully **contains** the chord; columns are the
12 keys; a cell marks whether the key is in that scale row. Reading column K shows which scale rows
survive playing key K as melody over the chord — i.e. which scale that melody note implies.

The scale names are empirical labels on results derived from the [subset principle](/docs/music/progression-principles#scales-from-the-subset-principle):
the four minor/bebop/harmonic scales are [`junction-scales`](#junction-scales) outputs, the major
scale is the `lcm-24` placement `24@k`, and major blues is the documented sub-selection of the bebop
dominant union (`24@0 ∪ 24@5` with the `lcm-24` roots removed).

12-tet only; `--chord-keys` is required. Chord keys are highlighted green; `●` marks membership. The
good-fraction options (`--max-size`, `--max-prime`, `--max-lcm`) are accepted for consistency but the
catalog is fixed.

### `chords`

```bash
melodroid table chords \
  [--ktet 12] [--min-notes 2] [--max-notes 7] [--max-results 1000] [--no-minor-seconds] [--allow-maj7] [--no-tritones] [--allow-dim] [--lcm-only] [--explicit-placements] \
  [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Enumerates the unique chords of a `--ktet` keyboard, deduplicated under **transposition**:
a chord and all its transpositions count once, so `0 4 7`, `0 3 8` and `0 5 9` are one chord.
Equivalently these are the binary *necklaces* of length `k` — for 12-tet there are 352 in
all (including the empty set and singletons), or 280 across the default 2–7 notes. Each row
lists the canonical key set (the most-compact rotation, transposed to start at 0 — the "normal
order" of set theory, e.g. the major triad as `0 4 7`) and its orbit size (the number of distinct
transpositions; symmetric chords like the augmented triad `0 4 8` have small orbits).
`--min-notes` / `--max-notes` filter by
note count; `--max-results` caps the rows. `--no-minor-seconds` (12-tet only) drops every chord
with a minor second (any two notes a semitone apart) — including the bare semitone dyad and the
whole major-seventh class, since on the chromatic circle a chord's seventh and root are adjacent.
`--allow-maj7` (12-tet only, implies `--no-minor-seconds`) relaxes this for chords with exactly
one semitone: the semitone is re-voiced to the octave boundary so the top note sits a semitone
below the octave and reads as a major seventh — the dyad `0 1` → `0 11`, and the major-seventh
chord `0 1 5 8` → `0 4 7 11`; chords with two or more semitones are still dropped.
`--no-tritones` (12-tet only, combinable with `--no-minor-seconds`) drops every chord with any
two notes six semitones apart, including tritone-stacked chords like the diminished seventh
`0 3 6 9` whose tritones are not adjacent gaps; unlike the semitone filter it has no re-voicing
relaxation, since a tritone survives every voicing.
`--allow-dim` (12-tet only, implies `--no-tritones`) relaxes this for diminished chords: a chord is
kept when every one of its tritones belongs to a diminished triad (`p, p+3, p+6`) present in the
chord — the diminished triad `0 3 6`, the diminished seventh `0 3 6 9`, and the dominant seventh
(shown in its compact necklace form `0 3 6 8`, which contains `0 3 6`); a chord with any
unjustified tritone is still dropped. A final
**Placements** column lists the LCM-family placements whose keys contain the chord — the inline
form of feeding the chord's key set to [`key-supersets`](#key-supersets). They are shown tightest
(fewest extra keys) first, each as `lcm@at` (the family LCM at the anchor key where its `1/1`
fundamental sits); any keys a placement carries beyond the chord are left implicit — inspect them
with `key-supersets`. By default, placements that cover the **same keys** (isomorphic families
sweep out identical key patterns, so their matching placements coincide — e.g. the major triad's
`3@7` and `4@0` both land on `0 4 7`) are collapsed to the lowest LCM; `--explicit-placements`
restores the full list. The list is capped per row, overflowing to ` …(+M)`, and is blank when no
family placement contains the chord.
`--lcm-only` (the **LCM approach** to chords) keeps only the chords that are a subset of at least
one available LCM family — i.e. it hides every row whose Placements column would be blank, leaving
the chords Harmonic Pattern Theory actually predicts. `--max-lcm` bounds which families count as
available: at the default 24 there are 102 such chords across 2–7 notes, collapsing to 20 when
capped at `--max-lcm 12` (only the isomorphic ≤12 group), which is where the tritone dyad `0 6` — a
subset of the lcm 15/20/24 families alone — drops out.
The good-fraction options `--max-size` / `--max-prime` / `--max-lcm` drive which families are
generated for the Placements column (and the `--lcm-only` filter).

### `progression`

```bash
melodroid table progression --origin-keys 0 4 7 \
  [--target-keys 3 7 10] \
  [--min-subset-notes 2] [--include-dim] \
  [--collapse-isomorphic] [--pool-maximal] [--all-bridges] \
  [--drop-collapsed none|origin|target|both] \
  [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

A command based on the two progression principles from the
[progression principles doc](/docs/music/progression-principles) ("Progression principles"). A
progression is a **triplet of placements** — an origin placement (contains the origin chord), a
target placement (contains the target chord), and a bridge placement fulfilling a principle:

- **superset** — some single LCM family placement contains both origin and target chords.
- **subset** — the chords origin and target placements share an lcm subset (e.g. C→Db: `15@7` and `24@8` both contain `18@10`).

The command has two forms (12-tet only):

**Standard form** (`--target-keys` given) — prints every origin→target progression as
**Origin | Bridge | Target** rows, superset rows first then subset. A superset row repeats the single
containing placement in all three columns. Subset rows are factored **both ways** around their shared
bridge `S`: every row collapses all origins that share the same bridge *and* the identical target
set, brace-listing both the origins and the targets (`{P_A, …} | S | {P_B, …}`). Each row is thus a
full `Origins × {S} × Targets` rectangle; it is lossless because the two containing placements are
always distinct (no origin can equal one of its own targets). Inside any brace list, placements that
share an LCM compress their anchors (`24@0, 24@5` → `24@0,5`). Beneath the table a per-principle
**placement summary** gives a quick read of the progression's topology — one anchor-compressed set
of the superset placements, and the subset placements split by slot into **origins** (`P_A`),
**bridges** (`S`), and **targets** (`P_B`); a principle's line is omitted when it has no triplets.
The footer reports the derived category.

**Convenience form** (`--target-keys` omitted) — enumerates every major/minor target triad rooted
at each of the 12 keys (add `--include-dim` for the 12 diminished triads too) and tags each with a
**Category**, split into **one table per triad quality**; unreachable **neither** targets are still
listed. The **Via** column shows the bridges: superset as an anchor-compressed brace list of
`{Lcm}@{At}` labels, subset as `P_A·S·P_B`
triples (capped at 6 per list, overflowing to `…(+M)`; `--all-bridges` disables the cap). Triples
sharing a source placement `P_A` and shared subset `S` are factored by that prefix, brace-listing
the varying target placements — `P_A·S·{P_B, …}` (a single target shows plainly as `P_A·S·P_B`);
within the brace list, same-LCM placements compress their anchors (`24@0, 24@5` → `24@0,5`).

Bridge/triplet lists are **raw by default** — plain `{Lcm}@{At}` labels, every containing placement
and every triple. By default output is truncated, use option `--all-bridges` to show all progressions.
Two independent, opt-in declutters shrink them **without changing any category**, exploiting the LCM-family lattice:

- `--collapse-isomorphic` — isomorphic families share a key set at shifted anchors (`3@7` and `4@0`
  are both `{0 4 7}`), so every placement is relabelled to its key set's representative, preferring a
  power-of-2 LCM (`3@k`→`4@k`, `9/10/12@k`→`8@k`), and deduped;
- `--pool-maximal` — only *maximal* containing placements `P_A`/`P_B` and *maximal* shared subsets
  `S` are kept (a placement whose keys are contained in another's is dropped). A chord's containing
  placement is kept as *all* of its incomparable maximal parents (e.g. `4@0` = `{0 4 7}` sits in both
  `24@0` and `15@7`, which are incomparable, so both are retained and `4@0` is dropped); a single
  underlying bridge can thus appear under more than one parent context (`24@0·S·P_B` *and*
  `15@7·S·P_B`) — intentional and lossless.

Pooling is lossless for reachability (if `S ⊆ P_A ∩ P_B` and `P_A ⊆ P_A'` then `S ⊆ P_A' ∩ P_B'`),
and the categories are computed from the **raw** placements regardless, so the category is identical
with or without decluttering.

`--min-subset-notes` (default `2`, dyads allowed) sets the minimum size of a bridging family `S` — raise it to tame the
"lots of dyads bridge everything" effect the doc warns about (at the default almost every target is
subset-reachable). The two containing placements in the subset test must be **distinct**: a single
placement holding both chords is classified as *superset*, so the subset principle fires only for
chords in different placements bridged by a shared subset.

`--drop-collapsed` (default `none`) disqualifies an unstable placement whose collapsing key is one
of the keys of the chord it contains — under the [preference principle](/docs/music/preference) such
a placement has already collapsed onto a smaller pattern and is not a valid bridge. Two families are
unstable: `lcm-15` (collapsing key `(At+8) mod 12`, collapsing onto an adjacent `lcm-24`) and
`lcm-20` (collapsing key `(At+3) mod 12`, since `20@At` is the subset of `15@(At+7)` and collapses to
it). `origin` applies the filter to the origin chord's containing placements `P_A`, `target` to the
target side `P_B`, and `both` to both sides. Because the categories and the triplets both derive from
these placements, a disqualified placement is removed from each. 12-tet only; other families are
untouched.

The good-fraction options `--max-size` / `--max-prime` / `--max-lcm` drive which families are
generated.

### `junction-scales`

```bash
melodroid table junction-scales \
  [--min-subset-notes 4] [--stable] \
  [--collapse-isomorphic] [--pool-maximal] [--dedupe-transposition] \
  [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

The **subset principle read as a scale generator**. The
[progression principles doc](/docs/music/progression-principles) defines the subset principle for
chord *progressions* — two placements `P_A`, `P_B` bridged by a shared LCM-family subset `S`. Read the
same structure as a *scale* and you get a **junction scale**: the key-union `P_A ∪ P_B`. This
recovers the useful non-LCM scales the [preference chapter](/docs/music/preference#blues-and-harmonic-minor)
decomposes by hand.

The command sweeps every distinct placement pair over all anchors that share a subset `S` of
`≥ --min-subset-notes` keys and prints one row per scale (12-tet only):

- **Scale** — the concrete key-index set to play, e.g. `{0, 2, 4, 5, 8, 9, 11}`.
- **Size** — number of keys.
- **P_A·S·P_B** — the constituents the scale was generated from.

**Stable form (`--stable`, default on).** A collapsing (prime-5: `lcm-15`/`lcm-20`) constituent
contributes its *stable* key set (collapse key dropped), and every collapsing constituent's collapse
key is then subtracted from the whole union. This is what makes **harmonic minor** fall out cleanly:

- `15@11 = {0 2 4 7 8 9 11}` (collapse key `(11+8) mod 12 = 7`), stable form `{0 2 4 8 9 11}`.
- `24@0 = {0 2 4 5 7 9 11}` — but `24@0` *independently* carries key 7, so it must be dropped from
  the finished union, not merely from `15@11`.
- Result `({0 2 4 8 9 11} ∪ {0 2 4 5 7 9 11}) \ {7} = {0 2 4 5 8 9 11}` = `harm@9`, generated as
  `15@11·18@2·24@0`.

With `--stable false` the raw unions are emitted and harmonic minor no longer appears (the union keeps
key 7).

**Blues is a looser member and is *not* a union output.** `24@9 ∪ 24@2 = {1 2 4 6 7 8 9 11}`, whereas
`blues@4 = {1 4 6 7 8 11}` keeps strictly fewer keys — neither `lcm-24` collapses, so no rule drops
keys 2 and 9. The command emits the full union (a superset of blues) and shows the `24@2·S·24@9`
triplet; blues itself is a manual sub-selection of that union.

**Decluttering.** `--dedupe-transposition` (default on) folds the 12 transpositions of each scale to a
single representative anchor (so harmonic minor shows once, as some transposition of
`{0 2 4 5 8 9 11}`); turn it off to list every anchored instance. `--collapse-isomorphic` and
`--pool-maximal` behave as in [`progression`](#progression), decluttering the `P_A·S·P_B` labels —
`--pool-maximal` in particular surfaces the maximal bridge, so harmonic minor reads as the clean
`15@·18@·24@` triplet rather than a small incidental subset. `--min-subset-notes` (default `4`) keeps
`S` a substantial `18`/`8` parent (harmonic minor's `S = 18@2` has 6 keys); lower it to admit smaller
bridges and many more scales.

## Graphs

### `lcm-families`

```bash
melodroid graph lcm-families [--mode full|collapsed] \
  [--max-size 24] [--max-prime 5] [--max-lcm 24] [--cluster-tolerance 0]
```

Writes a Mermaid relation graph to `output/graphs/`. `--mode collapsed` groups each isomorphism
class into a single node. In full mode each renormalized-subset edge is labelled with **every**
exact base at which the smaller family embeds into the larger — e.g. `9 → 24` lists both `4/3` and
`16/9`. Note these are *exact* good-fraction embeddings; keyboard placements from `table subsets` /
`table chord-melody` can show extra anchors (e.g. `24@10` for LCM 18) that exist only under k-tet
tempering and have no exact renormalization base here.

`--cluster-tolerance c` (default `0` = exact only) additionally draws **clustering-tolerant**
renormalized-subset edges (red dashed, `≈` label): a base whose renormalized images embed into the
larger family only after each image is snapped to its nearest good fraction within bin radius `c`
(the `c = (b−a)/(b+a)` metric of [Cluster Ranges](../theory/cluster-ranges)). When `c > 0` the file
is written as `lcm-families-clustered.md` so it does not overwrite the exact graph. Setting
`c ≥ 1/161 ≈ 0.00621` (the syntonic comma, = `MaxUniqueStandardBinRadius`) surfaces exactly one such
edge in the default space: `18 → 24` via `16/9` (the `24@10` placement), where `27/16` clusters onto
`5/3`. Remarkably, no other family gains a clustering-tolerant edge even at much larger `c`.

### `placement`

```bash
melodroid graph placement [--mode placement|extended|shape] [--lcm 1] [--at 0] \
  [--show-isomorphisms] [--max-size 24] [--max-prime 5] [--max-lcm 24] [--ktet 12]
```

Writes a Mermaid **placement graph** to `output/graphs/`, built from the key-set containment poset of
every placement (each LCM family swept over all `--ktet` anchors). Two placements are *adjacent* when
the larger key set contains the smaller, and *directly adjacent* (a **cover**) when no third placement
lies strictly between them; the edge label `+keys` gives the **distinguishing keys** the superset
adds. Keyboard-coincident placements (identical key sets, e.g. `3@3` and `4@8`) fold to one node,
keeping the power-of-2-preferred, then lowest-LCM, then lowest-anchor placement as representative. By
default each node shows just that representative `L@a`; `--show-isomorphisms` appends the folded-in
isomorphic placements with `≅` (e.g. `4@8 ≅ 3@3`). This flag affects `placement` / `extended` modes
only — the shape graph never lists aliases.

- `--mode placement` (default) — the `--lcm@--at` root (default `1@0`, the tonic) and its directly
  adjacent supersets only. Reproduces the tonic/dyad placement graphs in
  [Placements](../music/placements).
- `--mode extended` — the root's full **up-set**: every placement containing it, with all cover edges
  among them. `--lcm 4 --at 0` reproduces the extended triad placement graph.
- `--mode shape` — collapses every placement to its transposition-class **shape** and emits all 9
  shapes plus their 18 direct-adjacency relationships, each shown with one representative placement
  pair (`--lcm`/`--at` are ignored).

Because the graph is derived from the poset rather than hand-drawn, the extended triad graph includes
every hexad→heptad cover (any 6-key ⊂ 7-key placement is a cover, since nothing fits between them);
the figures in [Placements](../music/placements) are this command's verbatim output. 12-tet is the
intended keyboard; other `--ktet` values are allowed for exploration.

## Analyze

Commands that read an **external input file** and analyze it against the derived theory (grouped by
input rather than output type).

### `midi`

```bash
melodroid analyze midi --input song.mid \
  [--subdivision 4] [--merge-repeats] [--max-chunks 256] \
  [--bridges] [--min-subset-notes 2] [--collapse-isomorphic] [--pool-maximal] \
  [--ktet 12] [--max-size 24] [--max-prime 5] [--max-lcm 24]
```

Reads a MIDI file and discretizes it onto an **onset-quantized grid** of `--subdivision` slots per
quarter note (1 = quarters, 2 = eighths, 4 = sixteenths, …). Each non-empty slot's sounding notes are
folded to pitch classes mod 12 into one key-set; `--merge-repeats` (default on) collapses runs of
time-adjacent slots sharing an identical key-set into a single chunk (light "where the harmony
changes" preprocessing). For every chunk the table lists:

- the sorted pitch-class **key-set** and its size,
- the [LCM-family placements](#placement) containing it ([`FindSupersets`](#key-supersets),
  isomorphic-collapsed, capped), and
- the named [scales](#scale-fingerprint) containing it.

A chunk's harmonic identity is its key-set **plus these containments** — no traditional chord names
(per the first-principles anchor). The analysis is reference-free (all anchors are swept), so no key
or root need be supplied. `--max-chunks` aborts before rendering an oversized table; raise it, coarsen
`--subdivision`, keep `--merge-repeats` on, or use a smaller file. 12-tet only.

The per-chunk lists treat each chunk **in isolation**, so a chord *progression* — which lives in the
relationship between consecutive chunks — stays hidden. `--bridges` (default off) adds a second
**chunk-bridges** table: for each consecutive chunk pair it runs the pair through
[`progression`](#progression)'s classifier (`ChordProgressions.ComputePair`) and prints the category
(superset / subset / both / neither) alongside the superset (`{Lcm}@{At}`) and subset (`P_A·S·P_B`)
bridges between the two key-sets. Reading the **Superset** column top-to-bottom surfaces the
progression loop the per-chunk lists cannot — e.g. a C→F→G→C loop reads `8@5`, `24@0`, `8@0`. The
bridge-only flags mirror `progression`: `--min-subset-notes` (default 2) is the subset-principle
floor, and `--collapse-isomorphic` / `--pool-maximal` declutter the bridge labels losslessly (neither
changes the category).

Melody-movement / modulation tracking (how the melody walks the scale fingerprint to move between
placements) is a planned follow-up; this first cut establishes the per-chunk mapping.
