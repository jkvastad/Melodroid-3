# Voicings and Placements

We now have a $k$-TET tuning that can sound every full match, so we can start making music and
testing the model by ear. For the good fractions of max size 24 and max prime 5, 12 TET is the
tuning of choice, so we make a deep dive with these assumptions.

## Placements

In a 12 TET tuning the reference point of an LCM family full match maps to a key. We write a full match
of LCM $a$ with reference on key $b$ as $a@b$ (e.g. $24@0$) and call it a **placement** of the
LCM at key $b$.

Counting pitch C as key 0 lets us borrow familiar terms: $24@0$ is the C major scale, $4@7$ is
the G major chord.

Sometimes we must be explicit about the shape of a chord. We call this a **Voicing**, e.g. "$24@0$ voiced as `{7 11 2 5 9 0 4}`" is the G13 chord. 
This can help alleviate some dissonance from adjacent keys (e.g. `{0,1}` vs. `{0,13}`) or make the chord more playable by hand.

<Player keys={[0, 1]} label="▶ Close semitone {0, 1}" />
<Player keys={[0, 13]} gain={0.8} label="▶ Spread minor ninth {0, 13}" />

Neither sounds pleasant in a sustained tone, but the close semitone produces very audible beating effects as well.

Running

```bash
melodroid table placement --lcm 4 --at 0 --ktet 12
```

prints `4@0` (keys `0 4 7`, the C major triad). Option `--at 7` gives `4@7` (keys `7 11 2`, G major).
Pass multiple LCMs — `--lcm 3 5 15 --at 0` — to render one row per LCM at the same anchor, handy
for comparing isomorphic placements.

## LCM Family Overlaps
Sometimes we wonder if LCM families overlap. Running

```bash
melodroid table family-overlap --lcm-sweep 4 --lcm-ref 24 --ktet 12
```

compares the major-triad shape (LCM 4) against the C major scale (`24@0` = `{0 2 4 5 7 9 11}`). At
key 0 the overlap is `0 4 7` (the triad sits inside the scale); at key 5 the F major triad
`5 9 0` overlaps as `0 5 9`. Rows where the placement sits wholly inside the reference are
highlighted green.

## General Overlap
More generally we want to check an arbitrary number of keys against possible overlaps with lcm families. Running

```bash
melodroid table key-supersets --keys 0 4 7 --ktet 12
```

lists every placement whose keys contain the C major triad. The `Extra` column lists the keys a
placement adds beyond the requested set (empty = exact fit); rows sort by (extra count, LCM,
key). A few highlights from `{0, 4, 7}`:

| LCM | Key | Keys (12-tet)    | Extra      |
| --: | --: | :--------------- | :--------- |
|   3 |   7 | 7 0 4            |            |
|   4 |   0 | 0 4 7            |            |
|   8 |   0 | 0 2 4 7 11       | 2 11       |
|  12 |   0 | 0 4 5 7 9        | 5 9        |
|  15 |   7 | 7 8 10 0 3 4 5   | 8 10 3 5   |
|  24 |   0 | 0 2 4 5 7 9 11   | 2 5 9 11   |

The isomorphic `3@7` and `4@0` fit exactly; each larger family that contains the triad pads it
out with more keys, up to the full C major scale at `24@0`.

## Renormalisations expressed as placements
We earlier discussed [renormalisations of the lcm families](../theory/lcm-families.mdx#renormalisation-and-isomorphism).
Using the renormalizations command we could view the fraction sets from the perspective of each constituent fraction as reference point.

We can now express this as placements. Renormalising a family `L@0` onto one of its member
fractions `b` re-roots the *same physical keys* on the key `k` where `b` sits. Read as a placement,
those keys are simply another family `L'` anchored on `k`:

- when the renormalised set is an exact good family we get a placement **equality** `L@0 = L'@k`
  (an isomorphism — e.g. `4@0` = `{0 4 7}` onto `3/2` at key 7 is `3@7`);
- when it is a proper subset of a larger good family we get a **renormalised subset** `L@0 ⊆ L'@k` 
(e.g. `18@0` = `{0 2 5 7 9 10}` renormalised onto `4/3` at key 5 sits inside `24@5`).

Not every rotation lands on a good family. We keep only those that reach **both** a good LCM
(`L' ≤ 24`) **and** stay all-good within a **syntonic comma** (bin radius `c ≤ 1/161 ≈ 0.621 %`, see
[cluster ranges](../theory/cluster-ranges.mdx)). A rotation can satisfy one without the other: `24@0`
onto `5/3` keeps every fraction within the comma yet its nearest snap balloons the wave-pattern
length to lcm 120, so it is dropped. The `--placements` option computes this column directly:

```bash
melodroid table renormalizations --lcm 24 --approximate --placements
```

Sweeping every family `1..24` and keeping the good rotations gives the placements below, one row
per family (the trivial identity `= L@0` and the base fractions are omitted for brevity; an empty
row means the family has no non-trivial good rotation):

| Family | Renormalised placements |
| -----: | :---------------------- |
|   `2@0` | `⊆ 3@7` |
|   `3@0` | `= 4@5`, `⊆ 5@9` |
|   `4@0` | `= 3@7`, `⊆ 5@4` |
|   `5@0` | `= 6@3`, `⊆ 8@8`, `⊆ 9@10` |
|   `6@0` | `= 5@9`, `⊆ 8@5`, `⊆ 9@7` |
|   `8@0` | `= 9@2`, `= 10@4`, `= 12@7`, `⊆ 15@11` |
|   `9@0` | `= 8@10`, `= 10@2`, `= 12@5`, `⊆ 15@9` |
|  `10@0` | `= 8@8`, `= 9@10`, `= 12@3`, `⊆ 15@7` |
|  `12@0` | `= 8@5`, `= 9@7`, `= 10@9`, `⊆ 15@4` |
|  `15@0` | -|
|  `18@0` | `⊆ 15@9`, `⊆ 24@5`, `⊆ 24@10`* |
|  `20@0` | `⊆ 15@7` |
|  `24@0` | - |

`*` `18@0 → ⊆ 24@10` is the only rotation above that is not exact: its `16/9` base needs `27/16` to
snap to `5/3` within the **syntonic comma** (`c = 1/161 ≈ 0.621 %`, see
[cluster ranges](../theory/cluster-ranges.mdx)); every other placement is exact (`c = 0`).

Two features stand out. The two top families `15@0` and `24@0` have **no** non-trivial good
rotation — every other reference balloons the LCM or overshoots the comma.
And `18@0` is the sole family whose rotations reach *both* tops: `⊆ 24@5` and `⊆ 15@9` exactly, plus
`⊆ 24@10` only after `27/16` snaps to `5/3` at the syntonic comma.
